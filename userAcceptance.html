User Acceptance Testing

This page contains team Phoenix's effort to conduct User acceptance testing through the following Test plan:

Participants: For the purpose of this testing we chose individuals with and without a programming background. We targeted more technical feedback from persons with programming backgrounds and design and user experience feedback from those in other sectors.

Testing Period: Testing was conducted during the two-week period before the project's deadline since the application was mostly complete during by then.

Collection of results: Each person who took part in the testing was sent the link to the application and had to evaluate a specific aspect of it by providing feedback. All feedback was recorded on a Word document and moved to this page. The different segments users had to evaluate are presented in the following table.

Test Types

Test Test Type Test Description
1 Responsiveness The application is correctly formatted for mobile devices. All containers are displayed properly and font-sizes are adaptive.
2 Functionality The user can successfully add a username, choose a treasure hunt and begin a session.
3 Functionality Whilst trying to register for a treasure hunt, the user receives appropriate error messages when username or hunt are not specified, username is taken or the hunt is unavailable.
4 Functionality The user can answer questions with all possible answer types (True/False, text or numeric input and multiple choice).
5 Functionality A question is successfully skipped when the skip button is pressed.
6 Functionality A question cannot be skipped if it is specified as unskippable. An appropriate message is also displayed to notify the user.
7 Functionality The user is presented with appropriate messages which indicate whether a question has been answered correctly or not and how much score was gained or lost.
8 Functionality Users can access the qr code reader by pressing the camera button whilst playing.
9 Functionality The user can fully complete a treasure hunt session.
10 Functionality The user can view their placement on the leaderboard.
11 Functionality The application allows the user to continue unfinished sessions.
12 Design The application's design is consistent throughout all pages.
13 User Experience The application's design engages the user and ensures accessibility.

Response to feedback

-Application design shift from reds to light browns and light greys.

-Division styling was changed drastically towards simpler presentation.

-Function which displays messages with time delay was implemented to correctly display all messages whilst users are playing.

-Responsiveness was improved across all pages with media queries.

-Text font was changed to Arial Sans-Serif, compatible with all browsers.

-Fixed the issue which prevented the QR reader from opening
